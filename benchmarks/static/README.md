# Static-scanner precision benchmark (M23 #485)

Measures the govfuzz static ruleset's **precision / recall / false-positive rate**
per rule and per language against a labeled corpus. This is the number that makes
"best open-source static scanner" a measurable claim rather than a marketing line
— every new or edited rule must hold the precision floor or the gate fails.

## Layout

- `corpus/<lang>/` — labeled source. Each line where a finding is expected carries
  an inline annotation `EXPECT GF-NNN` (in that language's comment syntax). Every
  other line must stay clean. `vuln.*` files carry the positives; `safe.*` files
  are the tricky negatives (safe API variants that must NOT fire — parameterized
  queries, literal-only `eval`, `yaml.safe_load`, bounded copies, block `eval {}`,
  an API name mentioned inside a string).
- `results.tsv` — the scored baseline (regenerated by the runner).

## Running

```sh
cargo test -p static_analysis --test precision_benchmark -- --nocapture
```

The runner (`crates/static_analysis/tests/precision_benchmark.rs`) scans the
corpus, matches each finding to the `EXPECT` labels, computes TP/FP/FN, writes
`results.tsv`, and **asserts** overall precision ≥ 0.90 and full recall (no rule
silently stops firing). A rule change that introduces a false positive or drops a
detection fails the test.

## Scope & honesty

The seed corpus is govfuzz-authored and license-clean. It is deliberately small
and high-signal; expanding it with a permissive subset of NIST **Juliet** and
curated real-world positives/negatives (broadening the recall denominator) is
tracked as follow-up. The current number reflects precision on the curated set,
not a claim of exhaustive real-world recall.
